قُرّاء | QURAA — حزمة ميزات الأدعية (نسخة اختبار)
====================================================

الملفات:
- worker-staging.js: Worker الاختبار، مع الإبقاء على مسارات القراء والتلاوات وإضافة APIs الأدعية والمحتوى وإعداد بطاقة التذكير.
- public/admin-staging/duas.html: واجهة إدارة الأدعية (إضافة، تعديل، إظهار/إخفاء، حذف).
- public/admin-staging/dua-reminder.html: إعدادات بطاقة الدعاء ومعاينتها.
- public/dua-reminder.js: سكربت عرض البطاقة في صفحة الزوار عند إدماجه يدويًا.

تنبيه مهم:
1) هذه الحزمة لبيئة الاختبار فقط. لا تستبدل worker.js الإنتاجي ولا تنشر على الموقع الأساسي.
2) قبل تشغيل الواجهات، اضبط ADMIN_TOKEN في إعدادات Worker الاختبار واربطه بقاعدة D1 الحالية quraa-staging-db. لا تنشئ قاعدة بيانات جديدة.
3) انشر worker-staging.js عبر إعدادات الاختبار فقط بعد مراجعة التغييرات. الجداول الجديدة تُنشأ باستخدام CREATE TABLE IF NOT EXISTS ولا تحذف الجداول الحالية.
4) في صفحتي الإدارة، أدخل رمز ADMIN_TOKEN الخاص بالاختبار. الرمز يُحفظ في localStorage على هذا الجهاز فقط، ويمكن مسحه من أدوات المتصفح؛ لا تشاركه ولا تضعه في كود عام.
5) واجهة بطاقة الدعاء تحفظ إعداداتها، لكنها لا تُدمج تلقائيًا في الموقع. لعرضها على الزوار، أضف السكربت إلى صفحة اختبار الزوار بعد النشر، مثل:
   <script src="/dua-reminder.js" data-api="https://quraa-api-staging.quraaweb.workers.dev" defer></script>
   عدّل المسار حسب مكان استضافة الملف الفعلي. لا تضف السكربت إلى الموقع الإنتاجي أثناء الاختبار.
6) سكربت البطاقة مستقل، لا يتعامل مع عناصر audio/video ولا يوقف التلاوة ولا يعيد تحميل الصفحة. عند فشل API يفشل بصمت.
7) المسارات الإدارية محمية بـ Authorization: Bearer ADMIN_TOKEN. المسار العام /api/public/dua-reminder يعيد الإعدادات العامة والدعاء الظاهر فقط.
8) حاولت أداة GitHub المتصلة إنشاء فرع احتياطي ورفع ملف اختبار، لكن GitHub أعاد 403 Resource not accessible by integration. لذلك لم يتم استبدال ملفات المستودع أو النشر تلقائيًا؛ هذه ملفات جاهزة للمراجعة والرفع اليدوي إلى فرع الاختبار فقط.
